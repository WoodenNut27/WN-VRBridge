# WN-VRBridge 要件定義書

作成日: 2026-11-14

---

## 1. 概要

SteamVR の映像と音声を Meta Quest 3 に送り、Quest 3 の姿勢・入力・マイクを PC に返すリンクアプリケーション。

| 構成要素 | 役割 | 実行場所 |
|---|---|---|
| **ホストアプリ** | タスクトレイ常駐、設定画面、接続の待ち受け、SteamVR の起動、音声の処理 | Windows（独立したプロセス） |
| **SteamVR ドライバ** | 仮想 HMD とコントローラの登録、フレームの受け取り、エンコード、送信 | SteamVR の `vrserver.exe` の中（DLL） |
| **Quest クライアント** | 姿勢と入力の送信、映像のデコードと表示、音声の再生とマイクの送信 | Quest 3（Android ネイティブアプリ） |

- 開発言語: **C++**（C++20）。PC と Quest で通信プロトコルの実装を共通ライブラリにする。
- Quest 側の Android の土台（マニフェスト、権限）だけ必要に応じて最小限の Kotlin/Java を使う。
- 設定はすべて PC のホストアプリで行う。**Quest のクライアントには設定画面を設けない**（状態の表示だけ）。

---

## 2. 機能要件

凡例 — **MVP**: 最小構成で実装する / **後**: 後のアップデートで追加 / **任意**: 必要になったら検討

### 2.1 ホストアプリ（PC）

| ID | 機能 | 最小構成（MVP） | 完成形 | 区分 |
|---|---|---|---|---|
| H-01 | タスクトレイのアイコン表示、メニューから設定ウィンドウを開く | あり | 同左 | MVP |
| H-02 | スタートアップへの登録と解除（チェックボックス） | あり | 同左 | MVP |
| H-03 | 接続されたら SteamVR を自動で起動する | あり | 同左 | MVP |
| H-04 | 使う GPU の選択 | **RTX 4090 に固定** | 一覧から選ぶ。SteamVR の描画 GPU も同じものに合わせる。AV1 に対応しない GPU では AV1 を選べないようにする | 後 |
| H-05 | 待ち受けるネットワークアダプターの選択（一覧は自動で検出） | **検出した一覧から 1 つ選ぶ** | 「自動」を追加 | MVP／後 |
| H-06 | フレームレートの選択 | **72fps に固定** ※1 | 72 / 90 / 120fps | 後 |
| H-07 | 解像度の倍率 ※2 | **100% に固定** | 100% / 50% / 25% | 後 |
| H-08 | ビットレート（Mbps） | **固定値（150Mbps 前後を目安に調整）** | 手動の設定と自動調整 | MVP／後 |
| H-09 | エンコード形式 | **AV1** | AV1 / HEVC ※3 | 後 |
| H-10 | 接続状態と統計の表示（遅延、fps、ビットレート、パケットの喪失率） | 簡易表示 | グラフ表示 | MVP |
| H-11 | ログのファイル出力 | あり | ログの詳しさを選べる | MVP |
| H-12 | ペアリング（初めて接続する Quest をホストで承認） | 簡易版（確認ダイアログ） | 承認済み端末の管理 | MVP |
| H-13 | 設定の保存（`%APPDATA%\WN-VRBridge\` に JSON） | あり | 同左 | MVP |
| H-14 | SteamVR へのドライバ登録と解除（`vrpathreg`） | あり | 同左 | MVP |
| H-15 | Windows ファイアウォールの許可ルールの登録 | あり | 同左 | MVP |
| H-16 | 切断したときの動作（SteamVR を終了する / 残す） | SteamVR は残す | 選べるようにする | 後 |
| H-17 | 切断後の自動再接続 | — | あり | 後 |
| H-18 | Quest のバッテリー残量の表示 | — | あり | 後 |
| H-19 | USB 有線接続（adb のポート転送） | — | あり | 任意 |

※1 Quest 3 の表示の更新頻度は 72/80/90/120Hz で、60Hz に対応していない可能性が高い。60fps で送ると表示とずれてカクつくので、72fps を基本にする。実機で `xrEnumerateDisplayRefreshRatesFB` を呼んで確認する。
※2 映像を圧縮せずに送ることはできない（約 13Gbps 必要で、Wi-Fi の帯域を超える）。そのため「圧縮率」の代わりに **解像度の倍率** と **ビットレート** の 2 つの設定にする。
※3 H.264 は Quest 3 の両目分の横幅（4128px）が規格の上限（4096px）を超えるので、AV1 以外の選択肢は HEVC にする。

### 2.2 音声

| ID | 機能 | 方式 | 区分 |
|---|---|---|---|
| A-01 | PC の音を Quest で鳴らす | **WASAPI ループバック**（ドライバ不要）。できれば SteamVR のプロセスの音だけを録る（プロセスループバック） | MVP |
| A-02 | 接続中は PC のスピーカーをミュートし、切断したら戻す | 既定のデバイスをミュートする（ミュート中にループバックで録れるかは実装時に確認する） | MVP |
| A-03 | Quest のマイクを PC のマイクとして使う | **既存の仮想オーディオケーブル（VB-CABLE など）** を検出し、そこに音声を流す。ユーザーが自分でインストールする | 後 |
| A-04 | 接続したら既定のデバイスを自動で切り替え、切断したら元に戻す | `IPolicyConfig` を使う。**切り替える前の状態をファイルに保存**し、ホストが異常終了しても次に起動したときに戻せるようにする | 後 |
| A-05 | 「Quest 3 スピーカー / マイク」という専用デバイスとして見せる | 自作の仮想オーディオドライバ。署名（EV 証明書と Microsoft の署名）が必要。テスト署名モードはアンチチートと衝突するので使わない | 任意 |

### 2.3 Quest クライアント

| ID | 機能 | 区分 |
|---|---|---|
| Q-01 | 頭とコントローラの姿勢、ボタンとスティックの入力を送る（OpenXR） | MVP |
| Q-02 | 映像を受け取り、AV1 をハードウェアでデコードして表示する（`AMediaCodec` → OpenXR のスワップチェーン、描画したときの姿勢を付けて提出する） | MVP |
| Q-03 | PC から受け取った音声を再生する | MVP |
| Q-04 | 状態の表示（接続待ち / 承認待ち / 接続中 / エラー） | MVP |
| Q-05 | LAN 内の PC を自動で発見する（UDP ブロードキャスト） | MVP |
| Q-06 | PC が複数あるときの選択 | 後 |
| Q-07 | コントローラの振動 | 後 |
| Q-08 | マイク音声の送信 | 後（A-03 と合わせて） |
| Q-09 | ハンドトラッキング | 任意 |
| Q-10 | 視点の位置のリセット（リセンター） | 後 |
| Q-11 | パススルー表示 | 任意 |

## 3. 非機能要件

| 項目 | 要件 |
|---|---|
| 遅延 | 頭を動かしてから映像に反映されるまで（モーション・トゥ・フォトン）の目標は 50ms 以下。統計表示で測れるようにする |
| 安定性 | パケットが失われても映像が止まらないようにする（キーフレームの再要求など） |
| 互換性 | SteamVR の**公開されたドライバ API だけ**を使う。SteamVR 本体の置き換えやフックはしない |
| 互換性 | ホストとクライアントでプロトコルのバージョンを確認し、食い違ったら接続を拒否してその理由を表示する |
| セキュリティ | 承認した Quest だけを受け付ける。待ち受けるのは選んだネットワークアダプターだけ |
| 規約 | 接続先はユーザーのローカル PC だけ（Meta VRC.Quest.Streaming.2 に合わせる） |
| 復旧 | 音声デバイスの設定など、OS の状態を変えたものは、異常終了しても元に戻せるようにする |

| 項目 | 内容 |
|---|---|
| OS | Windows 11（64 ビット） |
| GPU（MVP） | NVIDIA GeForce RTX 4090（NVENC の AV1 エンコード） |
| SteamVR | 最新の安定版 |
| ヘッドセット | Meta Quest 3（開発者モードでサイドロード） |
| ネットワーク | PC と Wi-Fi 6/6E のアクセスポイントを有線で接続（10GbE / 5GbE / 2.5GbE） |

## 5. 技術構成

| 領域 | 使う技術 |
|---|---|
| SteamVR ドライバ | OpenVR Driver API（`IVRVirtualDisplay` から始める） |
| エンコード | NVIDIA Video Codec SDK（NVENC）、D3D11 の共有テクスチャ |
| 通信 | UDP の独自プロトコル（映像 / 姿勢・入力 / 音声 / 制御） |
| ホストとドライバの間 | 名前付きパイプ（設定、状態、統計のやり取り） |
| ホストの UI | Win32（タスクトレイは `Shell_NotifyIcon`）。設定ウィンドウの UI ライブラリは未定（Dear ImGui / Qt / WinUI 3） |
| 音声（PC） | WASAPI（ループバック、プロセスループバック）、`IPolicyConfig`（既定のデバイスの切り替え） |
| Quest | Android NDK、OpenXR（Khronos のローダーと Meta の拡張）、`AMediaCodec`、AAudio |
| ビルド | CMake。PC は Visual Studio 2022、Quest は Android Studio と NDK |

## 6. 開発の段階

| 段階 | 内容 | 主に対応する ID |
|---|---|---|
| 0 | 何もしない OpenVR ドライバを SteamVR に読み込ませ、仮想 HMD を出す | H-14 |
| 1 | Quest の頭の姿勢を UDP で送り、SteamVR の HMD を動かす | Q-01, Q-05 |
| 2 | 映像を最後まで通す（`IVRVirtualDisplay` → NVENC の AV1 → `AMediaCodec` → OpenXR） | Q-02 |
| 3 | コントローラ入力、音声（ループバック）、統計表示 | Q-01, Q-03, A-01, A-02, H-10 |
| 4 | ホストアプリ（タスクトレイ、設定、スタートアップ、SteamVR の自動起動、ペアリング） | H-01〜H-03, H-05, H-11〜H-13, H-15, Q-04 |
| 5 | **MVP 完成**。遅延の測定と調整 | — |
| 6 以降 | 「後」の機能（GPU 選択、fps、解像度、HEVC、マイク、自動切り替えなど） | 区分「後」 |
